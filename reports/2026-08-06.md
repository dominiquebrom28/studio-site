## The thing that wasn't on the backlog

`git status` at run start showed one untracked file:
`content/posts/2026-08-05-the-post-said-it-was-fixed.md`. It is a **complete,
`draft: false`, publish-ready 28-line logbook post** from the 2026-08-05
daily-logbook run. That run's branch, `team/2026-08-05-logbook`, has **zero
commits**. The session wrote the post and ended before committing it.

It survived because nobody ran `git clean`.

This is the **sixth** distinct work-goes-missing mechanism in this project,
and the first that is not a branch at all. The five before it: unchecked after
shipping (DOM-1/DOM-5); work destroyed by an in-branch merge (PR #81); a
phantom `[x]` manufactured by a merge (PR #87); the RECOVERED-section variant;
and check-offs simply never written (PR #100). Every check built for those
enumerates **branches** (PR #106) or compares **commits** (PR #103). Both are
structurally blind to a file that was never `git add`-ed.

Landed in PR #108 after fact-checking every figure in it against
`reports/2026-08-05.md`. Logged HIGH, with the fix belonging to the run
playbook rather than CI — CI cannot see an uncommitted file *by construction*,
the same class as the `npm install` drift trap.

## Three claims that did not survive being checked

### 1. "Skip the tail's `CommitLog` commit — that bug is already absent on `main`"

The backlog item and `docs/buildmode-tail-assessment.md` §5a both said so,
citing a measured ~404px clearance. frontend-dev checked instead of complying,
and the instruction was **wrong** — the measurement had been taken against
*unported* `main`, where the old `pt-[22rem] pb-[22rem]` caption padding was
incidentally supplying that clearance. Remove the captions and the padding goes
with them.

Measured in real Chromium at 1280px against built `dist/`: the last `<li>` sat
at **exactly 0px** from the `<details>` commit log — on **all six** project
pages, not just the two the item was about. Fixed with `mb-6` on the layout
container rather than porting the original commit, because section-to-section
spacing belongs to the container, not the leaf disclosure. Re-measured: 24px.

The original bug's root cause is worth restating as arithmetic rather than bad
luck: `w-56` (**224px**) fixed-width caption boxes anchored to a date axis
inside a **720px** column, with 5 phases averaging ~180px apart. They cannot
not overlap. That also explains why the six 2–3-phase pages were always clean —
this was never flaky, it was deterministic and simply unmeasured.

### 2. "Adding the compound-extension fix introduces no new false positives"

True as stated — against the file's existing "must never match" cases, which is
what devops verified. Measuring the widened regex against the **real corpus**
instead told a different story.

First, the fix itself found a genuine pre-existing bug: `PATH_TOKEN_RE` **never
matched a compound extension** in PR #91's shipped gate. `scripts/x.mjs`
matched; `scripts/x.test.ts` and `scripts/x.d.mts` never did, in any report,
ever. Every check script here ships both, so a Files-produced cell would have
silently dropped two of every three paths. 50 distinct real-corpus tokens
become extractable, all 50 genuine paths.

But the wholesale widening also made **bare extension fragments** match:
`` `.test.ts` ``, `` `.d.mts` ``, `` `.spec.ts` ``, `` `.generated.json` ``
appear **11 times** across `reports/` and `BACKLOG.md` as prose shorthand for
"files of this shape". They are not files, appear in no diff, and the first one
landing beside its own branch name would have failed the gate on a report that
had done nothing wrong — a false positive on the one gate whose header spends
forty lines arguing that a false positive *here* teaches people to ignore
report-writing gates specifically. Fixed by anchoring the name part's first
character to a non-dot; falsified by reverting it (exactly the new test goes
red) and restoring.

**The lesson is narrow and worth keeping:** "no new false positives" verified
against a test file is a weaker claim than it sounds. The corpus is the oracle.

### 3. "580 tests green"

They were — locally. PR #110's first CI run failed the `build` job.

Three real-corpus tests shell out to the **real `gh`**, deliberately: the
gate's ground truth is "does GitHub actually consider this PR merged", and
mocking that proves nothing about the part most likely to break. But `gh`
refuses to run inside Actions without `GH_TOKEN`. Locally it works via the
keyring, so the failure was invisible until it was pushed. This is the
environment-shaped verification lesson from PR #103 landing in a new place.

Per the playbook added in PR #97, the artifact was read **before** anything was
re-run — the log named the cause outright.

The fix is two-part, because the obvious one-part fix is a trap. `ci.yml` sets
`GH_TOKEN` on the `Test` step; and the tests skip when `gh` is unreachable
**only when `CI` is unset**, hard-failing under CI with the exact remedy in the
message. A plain `it.skipIf` would have turned a future missing token into
three silently-skipped tests and a green check — the green-but-covering-nothing
pattern this repo has now logged three times. Falsified in all three
environments: gh present → 33 pass; `CI=true` + broken gh → hard fail; no CI +
broken gh → 30 pass, 3 skipped, loud warning.

## Learnings

- **A plan that carries a measurement is still a claim.** The `CommitLog`
  instruction was measured, cited, and wrong, because the measurement predated
  the change it was advising. Measurements have an implicit "as of which tree",
  and this project has now been bitten by that twice in two days.
- **"Verified, no new false positives" needs an oracle stated.** Against the
  test file: true. Against the corpus: false. Neither party was careless; the
  claim was just narrower than its phrasing.
- **Making a network-dependent test skip quietly is how a gate dies.** The
  interesting part of the CI fix is not the token — it is refusing to let a
  future missing token become three silent skips. Skip conditions deserve the
  same suspicion as assertions.
- **The blast radius of a shared checkout keeps growing.** A post written by one
  scheduled task was found untracked by a different one. The collision hazard
  was logged as MEDIUM in July on theory; it has now cost, and nearly lost, real
  finished work.
- **Zero status drift in the Notion mirror, for the first time** — and the set
  comparison immediately found what status-only reconciliation cannot see. Both
  facts are the same lesson: a check that passes tells you only about what it
  looks at.
