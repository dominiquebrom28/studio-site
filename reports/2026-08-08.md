### The fix, and what it deliberately isn't

`vite` depends on `postcss@^8.5.6` and `postcss` on `nanoid@^3.3.12`. Both
patched versions were **already in range**, so `npm update nanoid postcss`
re-resolves them with no manifest change at all:

| package | before | after | |
|---|---|---|---|
| `postcss` | 8.5.19 | **8.5.26** | also clears moderate `GHSA-fxqj-rqcc-2cmp`, below the gate's threshold |
| `nanoid` | 3.3.16 | **3.3.18** | the blocking high |

Seven lines of `package-lock.json`. **No new `overrides` entry** — that would
pin a transitive dependency the repo does not own, for no benefit over a range
that already permits the fix. **No new allowlist entry** — `audit-ci.jsonc`'s
own standing lesson is that exceptions expire silently, and a second permanent
exception to dodge a one-command fix would be exactly the decay that file warns
about.

## Learnings

1. **A green gate result is a measurement with a timestamp, not a property of a
   branch.** `audit-ci.jsonc` already carries a standing lesson that allowlist
   entries expire because advisory *ranges* get widened. This run found the
   verification-side twin: PR #114's six green gates were real and were stale
   within a day, because a *new* advisory published against an unchanged
   dependency. The repo now has both halves written down. Re-run an unblocker's
   gate at merge time, not once at authoring time.

2. **The most dangerous PR to trust is the one that says "merge me first."** It
   is precisely the PR a reader is least likely to re-verify — it arrives with an
   urgent, well-evidenced claim and an implicit request to skip ahead. This one
   earned that trust on 08-07 and did not deserve it on 08-08, through no fault
   of its author.

3. **A mirror that disagrees with the source of truth is not automatically
   wrong.** The reconciliation rule assumes the previous run's bookkeeping PR has
   merged. With a queue two days deep it hadn't, the mirror was tracking reality
   better than `main` was, and following the rule literally would have destroyed
   8 correct rows. This is the same shape as the 2026-07-19 lesson — *a gate that
   fails should be suspected as hard as the content it fails on* — applied to a
   sync rule instead of a CI check.

4. **Three advisories in five days against unchanged dependencies is a base
   rate.** It was tempting to read `undici` → `js-yaml` → `nanoid` as a run of bad
   luck. It is more useful to read it as the actual frequency at which this
   dependency tree goes red on its own, which makes a PR-only trigger
   structurally insufficient rather than merely imperfect.

5. **A snapshot that pins a growing number is a gate with an expiry date.**
   `toHaveLength(1)` on an advisory list was correct the day it was written and
   went red when the studio did something entirely healthy twice. This is the
   third distinct expiry mode this project has now recorded — an allowlist entry
   whose advisory range widened (`audit-ci.jsonc`), a verification result
   overtaken by a new advisory (learning 1), and now an assertion overtaken by
   normal growth. The common shape: **each was true when written, and none of
   them had any way to announce that it had stopped being true.**

6. **Throttled runs should spend their surplus on verification, not volume.**
   With no capacity to ship, the highest-value thing available was proving that
   the one change on the table was both necessary and inert. Two extra installs
   to byte-compare a stylesheet is a poor use of a busy run and an excellent use
   of a blocked one.
