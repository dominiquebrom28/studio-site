## What was done

### #116 — a `git merge main` resurrected code the branch had deleted

`npm run typecheck` failed with six `TS2304`/`TS2552` errors: `itRealCorpus`,
`REPO_ROOT` and `realGh` undefined in `scripts/check-backlog-checkoffs.test.ts`.

Cause: commit `2142989` **moved** the real-corpus `describe` block (and those
three helpers) into a new `check-backlog-checkoffs.real-corpus.test.ts`, making
the default `npm test` hermetic. The later in-branch merge `ea05490` pulled in
`main`, which still had that block in the old file. Git resolved delete-on-one-
side / modify-on-the-other by keeping main's modified copy — **no conflict
markers, no warning** — so the block came back without the helpers that had
left with it.

devops verified the diagnosis rather than taking it, and specifically checked
that deleting the resurrected block loses **no** coverage: all three tests exist
in the new file, and the only assertion present in the old copy and absent from
the new one is a `runs-api` pin that was deliberately removed with a 30-line
rationale. Two defects would have come back with the block: that latent-red pin,
and a comment naming PR #108's branch as `team/2026-08-05-stranded-records`
(`gh pr view 108` says `-08-06-`).

A tombstone comment now sits at the exact line the block keeps landing on,
naming the symptom and the remedy, so the next `main` merge that resurrects it
is diagnosable in seconds rather than hours.

**Falsified:** restoring the block reproduces all six errors byte-identically to
CI run 31617211930 (`tsc -b --noEmit` exit 2); removing it returns exit 0.
603 tests green; `test:real-corpus` genuinely *ran* (8 tests, real `gh`
latencies) rather than skipping.

### #117 — the weaker gate was masking the stronger one

`npm run check:report-claims` failed claiming two reports named files their
branch does not touch. Two prior runs read that as "a report is lying".

**It wasn't.** Both claims were true when written. The 2026-08-12 in-branch
`Merge branch 'main'` (`713489b`) resolved two files entirely in main's favour
and silently deleted the branch's own work: the whole `2026-08-07`…`2026-08-11`
block of `src/content/runs.generated.json` (−35 lines) and `db25190`'s pin
removal in `scripts/check-backlog-checkoffs.test.ts`.

**This repo's own gate already said so.** `npm run check:merge-revert` printed a
two-path VIOLATION naming the exact merge commit. Nobody saw it, because CI runs
`check:report-claims` (`ci.yml:178`) *before* `check:merge-revert` (`ci.yml:205`)
and stops at the first red. The gate built for precisely this incident class
(PR #81) was standing four steps behind the one that produced a misleading
diagnosis, for six days.

Fix: both files restored to the branch's own pre-merge content — **zero report
prose edited**. Correcting the tables would have deleted true history to satisfy
a gate and left both real losses in the tree.

### #117, second pass — a gate that was scanning the wrong table

With the merge revert repaired, `npm test` went red for a *different*,
pre-existing reason (proven pre-existing by stashing the fix and re-running):
`extractItemRows` matched **any** table with a `branch`-prefixed header and an
exact `pr` header, treating `item` as optional. That made it read
`reports/2026-08-11.md`'s "Verified merge plan for Dom" table — a merge-**order**
rehearsal of eight *other* PRs — as an items-worked-on table, and demand
`BACKLOG.md` check-offs for daily logbook branches that have no backlog items and
never will.

Lead decision: **fix the gate, do not reshape the report.** The gate's documented
input contract (BACKLOG.md, "'Items worked on' table") is
`| Item | Branch | Files produced/changed | PR |`, so requiring the `Item` column
is not a relaxation — it is the gate finally matching the shape it says it
consumes. Reshaping the report would have edited true history to satisfy a
shape-guess and left the defect live for every future report.

Because a gate that silently covers **less** is this project's worst failure
mode, the change was gated on a full-corpus sweep before it was committed: every
markdown table in all 35 reports, old condition vs new. The sweep's own row total
was cross-checked against the real `extractItemRows()` (43 vs 43) so it could not
diverge from the thing it was measuring.

**Result: 11 tables / 43 rows → 10 tables / 35 rows. Exactly one table dropped**
— the merge-plan table — and **zero** real items tables lost, across three
distinct header shapes including a `| # | Item | Branch | PR |` variant with a
leading column. The 08-11 items table's two genuine rows still scan.

Falsified both directions: a merge-plan table is not scanned, a canonical items
table is. `npm test` 590/590, from 586 passed / 1 failed.

## Learnings

- **Nobody was checking the studio's own homework.** Four scheduled runs
  fast-forwarded `main`, reconciled Notion, planned, and opened more PRs while
  two of their own PRs sat red. The red *was* surfaced — `notify-on-failure`
  commented on both PRs, exactly as designed. The gap is that no run reads its
  own queue. A studio that ships a gate for everything and never asks "is my
  queue green?" is the joke writing itself.
- **Gate order is part of a gate's design.** Two runs chased "a report is lying"
  because the symptom gate ran before the root-cause gate and CI stops at the
  first red. The better gate existed, was correct, and was invisible. Ordering
  cost six days.
- **`git merge main` cost this project two PRs on the same day, in two different
  ways** — one path-granular (caught), one intra-file (not caught, because
  `check-merge-revert` compares paths and the file survived). The remediation
  text in that script already says "prefer `git rebase main` on report/backlog
  branches"; nothing enforces it, and this is the second logged instance.
- **"Grep found nothing" is evidence about your checkout, not your project.** On
  a repo whose backlog is one file every open PR edits, an agent standing on
  branch A cannot see an item added on branch B — and will confidently report it
  missing. I made that exact mistake in a commit message this run.
- **A deferral's price tag expires.** The `react-router` allowlist entry was
  honest, well-argued and correct when written. Advisory ranges move in *both*
  directions, and this one narrowed — turning a 28-file migration into a patch
  bump with nobody noticing for nine days. The file's own STANDING LESSON
  anticipated widening ranges; it did not anticipate that good news also needs
  re-checking.
