### P1 — Vercel full-clone (PR #48) · devops

The generator hard-fails on shallow clones *by design* (§5.2: a shallow clone
doesn't error `git log --diff-filter=A`, it silently truncates it, which would
turn an infra failure into a false "no commit yet" claim on the live site).
Vercel shallow-clones by default, so the first deploy after #52 would have
failed loudly.

Fixed in-repo via a `buildCommand` that un-shallows first. The reasoning worth
recording: `|| true` is safe here **only because** it swallows nothing but the
already-complete-clone error — a genuinely shallow repo still trips the
generator's own guard moments later. The fail-loud property is preserved, not
bypassed. A dashboard-only `VERCEL_DEEP_CLONE=1` fix was rejected as the
primary mechanism because it can't be verified or enforced from the repo.

## Learnings

**An agent overrode its brief and was right.** The conversion-path dev was told
the binding phrase was "the ten AI characters". It checked `persona-bible.md`
and `design-brief.md`, found the binding form is the **numeral** "10 AI
characters", and shipped that instead — noting design-brief §7 names the footer
specifically. Lead-verified: the docs back the agent, not the brief. The lead
relaying a spec is a lossy step, and specialists reading primary sources is
what catches it.

**The most valuable output of the run was a bug nobody asked for.** The
Playwright lane's first real run found `Callout`'s `watch-out` tone at 4.45:1 —
below the 4.5:1 AA floor. The design brief's hand-computed table says 4.69:1,
but it only ever checked `--warning` against flat `--paper`, never the
`color-mix()` wash the component is actually rendered on. Every existing
`axe.run()` in the repo silently skips `color-contrast` because jsdom has no
canvas. So a "verified AA" claim had been sitting in the brief, untestable, for
nine days. This is the third instance of the same pattern in this project's
history: **the claim was documented, the verification was structurally
impossible, and nothing flagged the gap.**

**Falsification caught a bad test, not just bad code.** While proving the
provenance tests fail correctly, the dev found `toThrow(/provenance:generate/)`
passed against *both* failure branches — a test that would have green-lit the
wrong error path. Falsifying tests catches weak assertions, not only missing
implementations. Worth keeping as a standing practice.

**Two scheduled tasks are sharing one checkout.** This run found the main
checkout on `team/2026-07-23-logbook` with a fresh commit — `daily-logbook`
running concurrently in the same directory. PR numbers interleaved across the
two sessions. No damage, only because this run had already moved everything
into separate worktrees. That was luck dressed as process; filed as a MEDIUM
item.

**CI can't catch local-only drift.** `axe-core` merged into `package.json` with
PR #43 but was never installed locally, so `npm run build` and `typecheck`
failed repo-wide today. CI runs `npm ci` and was perfectly green throughout —
which is precisely why nobody noticed for a day. The first agent to hit it
spent real effort proving the breakage pre-dated its own branch.

**Five parallel agents in hand-made worktrees worked.** Five specialists ran
concurrently with zero branch collisions using `git worktree add` plus a
symlinked `node_modules`. One wrinkle: an agent that runs `npm install` gets
its symlink replaced by a real local `node_modules` — safe, but it silently
stops sharing the cache.
