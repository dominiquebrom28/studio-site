## Decisions made

- **Excluded three project files from the provenance backfill** rather than produce a fuller-looking page. Falsifiability over completeness; a new test pins those three as `undefined` forever so a future report can't quietly mis-claim them.
- **Resolved `project-page-v2.md` §7's objection by disambiguating, not overruling.** Its worry — that a provenance strip would misattribute the *software's* authorship on Dom's solo builds — was legitimate but aimed at a different claim than the strip makes. Fixed with explicit copy ("this note is about how the page describing it was produced, not the software itself") that adapts off `project.soloBuild`, so a future team-built project won't inherit a false claim.
- **CLS: measured, tracked, deliberately not fixed.** The item was scoped as measurement; reserving space for lazy routes is a layout decision that deserves a designer. Logged as its own HIGH item with a delete-on-fix instruction, following PR #57's precedent.
- **INP not asserted at all.** It's a field metric. A labeled synthetic proxy is measured and never called INP — calling a lab number INP is the exact "green but covering nothing" pattern that has burned this repo four times.
- **Left non-ASCII slugs alone**, with a pinning test. The item asked for a decision, and the evidence (no current post affected; ASCII-only matches the existing slug convention) supports "leave it."
- **Did not recompress the hero PNGs.** `pngquant`/`oxipng`/`cwebp` are all absent from this machine. Reported with measured evidence rather than half-fixed with the wrong tool.

## Learnings (blog-worthy)

- **"Measurement, not optimization" found the thing the reasoning had ruled out.** The performance item argued the groundwork was already in place — click-to-play so no GIF can be LCP, dimensions declared, small `dist/` — and concluded this was a formality. All of that was true, and the site still fails CLS by 4×, because the shift comes from the *route loading state*, not from any image. The reasoning was locally correct and globally wrong. The only thing that caught it was actually measuring.
- **A falsification that fails to fail is data.** Stripping `width`/`height` off `MediaGallery` items changed CLS by exactly zero — because those images are lazy and below the fold, never fetched inside the window. The temptation is to quietly drop the falsification that didn't cooperate. Reported as a named coverage gap instead: the protection people *think* those attributes provide isn't being verified by anything.
- **Three of this run's five lanes shipped something green that didn't work.** An unreachable link, an artifact that would upload empty, a selector that would match the wrong element. None would have failed a gate; all three needed someone to ask "but does this actually do the thing?" That is now four consecutive runs where lead review or browser verification caught what the gates could not — which stops being an anecdote and starts being the argument for why the review step is the product, not the overhead.
- **The environment lied convincingly.** PR #72's dev server threw `Invalid hook call … more than one copy of React` — a plausible P0. It was five parallel worktrees sharing one `node_modules/.vite` dep cache. The tell was three different `?v=` hashes in the stack traces; the proof was re-running against `vite preview` on `dist/`, where the optimizer plays no part. Both failure modes are bad: reporting a false P0, or dismissing a real one because "it's probably the worktree." The way out was neither guess — it was finding a surface where the variable couldn't exist.
- **The backlog's own framing can be the bug.** The performance item pointed the fix at "the now-image-heavy project pages." The images were nearly irrelevant. An item written from a plausible cause quietly narrows where the next run looks.

## Provenance blocks

**None — deliberately.** This run created no content files. Everything it
produced is infrastructure, tests, docs and reports: `e2e/perf-budget.spec.ts`,
`docs/performance-budget.md`, `src/lib/csp/distIndexHash.test.ts`,
`src/lib/githubLinks.ts`, CI steps and this report. The generator joins
`produced` paths against `git log --diff-filter=A` to render the strip on posts
and project pages; nothing here renders on either, so a block would carry no
signal.

Two blocks were drafted and removed on inspection, which is worth recording
because both were wrong in ways the format is designed to catch:

1. A block claiming `docs/performance-budget.md` and `e2e/perf-budget.spec.ts`.
   Those files were created on `team/2026-07-29-perf-budget` (PR #73) and do not
   exist on this branch — the generator would have hard-failed on dangling
   paths, exactly as spec §5.2 intends. A report may only claim what its own run
   created.
2. A block claiming `reports/2026-07-29.md` itself. Every `produced` path in
   every existing report is under `content/` — reports are the *source* of
   provenance, not a subject of it.

Per the "Run report format" rules below: forgetting a block is self-correcting
(the site shows "no run record"), so the failure mode to avoid is inventing one
to fill a gap. That applies to a run with nothing to claim as much as to a run
that forgot.
