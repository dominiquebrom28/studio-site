### The 5 nits and what got fixed, and why
1. **"Malformed frontmatter fails the build" was inaccurate** — `vite build`
   doesn't execute app modules, so a Zod throw surfaces in dev / at runtime, not
   during the prod build. *Fixed:* build-time enforcement now correctly comes
   from CI running the loader tests / a `validate-content` script, with route
   error boundaries catching runtime cases. Matters because the frontend dev
   would otherwise trust a gate that doesn't exist.
2. **`gray-matter` has Node/`Buffer` assumptions** that can throw in a browser
   bundle. *Fixed:* added a caveat naming browser-safe fallbacks
   (`front-matter` / `js-yaml`). Saves the scaffold phase a debugging detour.
3. **Only 2 of 6 project files were shown** in the folder example. *Fixed:*
   enumerated all six (soulforge, pizzaparty, mensapp, lovediary, portfolio,
   chart-token-playground) so the content writer has no lookup.
4. **`react-router-dom` pinned to "v6"** while v7 is current. *Fixed:* "pin
   latest stable at scaffold time," noting the small API delta.
5. **Error boundaries were under-credited** given nit 1. *Fixed:* folded the
   connection into the rewritten loader section.

## Decisions made (from the spec, worth surfacing)
- **Content = `import.meta.glob` + gray-matter + Zod, no CMS.** Git is the CMS;
  Zod schema is the single source of truth and fails loudly on bad content.
- **SPA via react-router, not Astro/Next SSG.** Stack consistency wins for v1;
  the honest downside (weaker per-page SEO / social previews) is documented with
  a pre-identified SSG migration path.
- **Security scoped honestly:** only 4 categories genuinely apply to a static
  markdown site (markdown-render XSS, secrets/env hygiene, source maps +
  headers/CSP, dependency supply chain). Everything else (auth, RLS, injection,
  CSRF, payments, tenancy, rate limiting, observability) is ruled out *by name
  with a reason* — not skipped.
