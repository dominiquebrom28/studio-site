## Learnings

**Adversarial QA pays exactly where the code's job is honesty.** The
provenance engine shipped with 57 self-tests, every failure-table row
covered — and still had a silent-pass path (directory-as-produced-path) that
only hostile probing found. The engine's whole purpose is that wrong records
fail loudly; the one gap was a record that succeeded quietly. On
data-integrity code, the QA gate isn't a formality — it's the only gate
whose incentive is to make the thing lie.

**"Dead code" is a verdict, not an observation.** The unused `triggerRef`
looked like cruft; deleting it would have passed every gate. Investigating
*why it existed* revealed the focus-return path it was meant to serve was
silently broken for mouse users — the fix was wiring, not deletion. The
2026-07-21 review flagged it as "a dead ref a test would force resolving,"
and that's precisely what happened.

**Live deployments are a capture asset.** DOM-4 stalled three runs partly
because it was framed as "run four dev servers." Three of the four projects
were already deployed — shooting production URLs took no setup, no branch
risk, and no classifier exposure. The framing of a task's prerequisites can
cost more than the task.

**A queue that empties itself changes the throttle math.** PR #41 merged
before the run started (branch protection + auto-merge doing its job), so
the review-capacity constraint that shaped the last three runs simply wasn't
binding today. The infra items from 07-17 are now visibly paying rent.

*No `yaml provenance` blocks for this run: it created no `content/` files
(assets and code only), so there is nothing the provenance device could ever
render from a block here — and the engine that would consume it (PR #44)
isn't merged yet. First run to state this explicitly under the new format
rule; the first real blocks land with the backfill (spec §12 PR 6).*
