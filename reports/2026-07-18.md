qa-tester passed it **88/100** and fixed three real bugs: two TOC/DOM anchor

**Then browser verification found the live app was 0/3.**

Every TOC anchor was dead. Rendered `<h2>` ids carried a `-1` suffix
(`the-cleanup-sweep-1`) while the TOC pointed at `#the-cleanup-sweep`. Cause:
`Markdown.tsx` created a heading-id `Map` in the component body and **mutated
it during render**. React StrictMode double-invokes render precisely to expose
impure renders, so the second pass saw every heading as already-seen and
de-duplicated against the first pass's own output. QA's harness renders once,
so it could not reproduce it — 21/21 and 0/3 were both accurate measurements
of different things.

Two more browser-only findings in the same pass: "Written by Project Lead"
rendered twice at 1280px (both `Byline` and `ProvenanceStrip` owned that
sentence), and the signature read *"Signed, Project Lead, Understands the
request, breaks it into tasks, deploys specialists, reviews and synthesizes
the result"* because `cast.ts`'s `role` field is a job description, not a
title.

frontend-dev's fix round made id derivation structural rather than
coincidental: one internal `scanH2Headings(body)` that both
`extractTableOfContents` and a new pure `headingIdsByLine(body)` project from,
with the `h2` renderer doing a read-only lookup keyed by the heading's real
source line from the AST. A lookup cannot accumulate state, so it is
idempotent by construction. `ProvenanceStrip` now owns "Written by"; a short
`title` field was added to the cast entries (compressions of existing `role`
text — no new claims about any character) with an invariant test that every
title is non-empty, ≤40 chars, and strictly shorter than its role.

Re-verified in the live browser afterwards: h2 ids and TOC hrefs identical,
**zero dead anchors**, one byline, `Signed, Project Lead, Delegates and
reviews`, mobile order correct, TOC hidden below `lg`. **104 tests green.**

## Learnings

- **A verification method's blind spot is invisible from inside it.**
  qa-tester measured TOC/DOM parity at 21/21 across a deliberately nasty
  21-case matrix. That number was correct and the feature was still completely
  broken, because the harness rendered once and the bug only exists on the
  second render. The lesson isn't "QA was sloppy" — it was rigorous. It's that
  a passing score tells you the harness's assumptions held, not that the
  feature works. Only a different *kind* of check finds that class of bug.
- **StrictMode paid for itself.** The impure render would have been a subtle,
  intermittent, near-unfindable bug in production. StrictMode's double-invoke
  turned it into a loud, deterministic, trivially reproducible one. Worth
  remembering the next time double-rendering looks like an annoyance.
- **Three for three: the worst bug of the run was browser-only.** Hero token
  collision (07-15), mobile reading order (07-17), dead anchors (07-18). Each
  passed every automated gate; each was caught by a human opening a page. That
  is now a pattern with a cost attached (the 226k-token fix round), and it is
  why a browser-level CI check went into the backlog as the top item.
- **"Unchecked" still didn't mean "unbuilt" — but this time it meant "live and
  wrong."** The projects-pages run learned that backlog checkboxes lie about
  what exists. This run found the sharper version: the "First blog post" item
  was unchecked because the post was a *placeholder that was already published*
  with `draft: false`. The site had been telling visitors "the honest write-up
  lands in a later run" for three days. Reading the actual content, not just
  the file listing, is what surfaced it.
- **A missing source is a finding, not a blocker.** The backlog told marketer
  to source the founding post from a `claude-dev-company` repo that no longer
  exists. It searched, found nothing, said so, and re-sourced from the live
  config — then put that fact in the post's own opening paragraph. The
  temptation to reconstruct a plausible history of a repo nobody can check is
  exactly the failure mode this studio is built to avoid.
- **Fixing the bug versus fixing the class of bug.** The cheap fix for the dead
  anchors was to reset the counter or wrap it in a ref. The fix that shipped
  made TOC and DOM ids two projections of one scan, so they cannot drift even
  in principle. The first would have closed the ticket; the second closed the
  category.
