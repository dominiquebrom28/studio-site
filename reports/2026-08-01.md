## 5. Dependency-drift preflight — PR #86

CI runs `npm ci`, so it structurally cannot catch a stale local
`node_modules`. That is why the 2026-07-24 breakage went unnoticed for a day
and cost an agent real time proving it pre-dated its own branch.

`scripts/check-deps-drift.mjs` reports **three** states — `clean` / `drift` /
`inconclusive` — with the third existing solely so a missing `node_modules`
can never be reported as fine. Given three prior incidents of a check going
green while checking nothing, a fourth was not worth adding. It never runs
`npm install` itself; it names the packages and prints the fix.

It fires from committed `.githooks/{post-checkout,post-merge}` wired through
`core.hooksPath`, chosen over `.git/hooks/` because that directory does not
propagate to a `git worktree` — which every lane in this run used. Also
worktree-aware in a way that matters: on drift it resolves a symlinked
`node_modules` and points the fix command at the real target, because running
`npm install` inside a worktree replaces the symlink with a private copy and
silently stops sharing the install, a hazard already sitting in the backlog.

**Lead review found one real defect:** the `prepare` script set
`core.hooksPath` unconditionally, so `npm install` would silently overwrite a
hooks path someone else had configured — disabling an unrelated husky or
lefthook suite as a side effect of installing dependencies. That is the same
"automation mutates your setup without telling you" shape the script's own
header argues against. It now refuses and reports, falsified across all three
starting states (unset → sets; already `.githooks` → idempotent; `.husky` →
left intact).

**Flagged for Dom rather than buried:** merging this means `npm install` sets
repo-local git config. Deliberate, and the only mechanism that survives
worktrees — but a conscious call.

## Learnings

- **A read-only mirror can become the only record, and that failure is
  silent.** The Notion sync is documented as a one-way mirror of a source of
  truth. For one day it was the *sole* holder of four findings, because the
  step that writes them to the source of truth was reported as done and
  wasn't. The mirror worked perfectly; that is what made the gap invisible.
  Anything downstream of a report's own claims about itself is unverified.
- **Reports are the last unaudited artifact in this project.** Every content
  file is Zod-validated, every route is smoke-tested, both generated artifacts
  are drift-gated — and a run report can assert "this branch contains
  `BACKLOG.md`" with nothing checking it. The cheapest possible gate would
  compare a report's claimed branch contents against `git diff --name-only
  main...<branch>`. Worth building precisely because it is the shape of failure
  this project keeps having: not a wrong value, but a claim nobody checks.
- **The number you didn't measure is the one that's wrong.** This run
  corrected its own PR body — "12 → 15 records" when `main` holds 11 — and the
  portfolio draft's "two-thirds of that backlog" when the finding was about the
  queue. Both were written by careful agents that measured most of their
  figures. The pattern is that the *incidental* number, the one carried along
  to give context to the number you actually care about, is the one that goes
  unchecked.
- **The idea worth taking seriously is the one you expect to win.** Option 4 of
  the provenance ordering question was genuinely the more elegant design and
  the expected answer. It lost to three specific facts in `parse.mjs`,
  `ProvenanceStrip.tsx` and the reports-surface spec — none of which were
  guessable, all of which were one `grep` away. A design argument settled by
  reading the code is worth more than one settled by reasoning about it, and
  it took about twenty minutes.
- **A one-day throttle stop paid for itself.** The 07-31 run built nothing
  because the queue was over throttle, and spent itself on diagnosis instead.
  Dom then merged seven PRs in twelve minutes. The throttle is not lost
  capacity; it is the mechanism that converts review-capacity pressure into
  something a run can act on.
